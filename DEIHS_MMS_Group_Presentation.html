Project Objective & Scope

Objective

  • Build a feature-complete maintenance management system for DEIHS (facility/equipment issues, tracking, records, monitoring, and user management).

Target Users / Roles

  • School Administrator — full system management & approvals
  • Maintenance Head — oversight, assignment coordination, reports
  • Maintenance Personnel — assigned tasks only (My Tasks)
  • Teacher / School Staff — submit and track own requests (My Requests)

Deployment

  • Multi-PC LAN: shared MySQL (XAMPP/MariaDB) host + JavaFX client PCs

Technology Stack & Architecture

Stack

  • Java 21, Maven, JavaFX 21.0.13 (FXML/CSS), MySQL Connector/J, HikariCP, jBCrypt, PDFBox, Gson

Architecture

  • MVC-style: FXML Views + Controllers, Services (permissions/validation/rules), DAOs (JDBC), MySQL schema
  • Centralized config (db.properties / -D overrides) for LAN host, DB, and Google OAuth
  • Session + role-based permissions enforced in service/UI flow

Database

  • Core tables: users/roles, facilities, equipment, maintenance requests/categories/records/schedules, comments/history/attachments, audit_logs, account_requests

Completed Modules (1/2)

Authentication & Accounts

  • Login (DB role-based), self-registration → pending admin approval
  • Google sign-in/sign-up scaffold (Option A: match verified email; new users submit pending request) — config-gated, needs real OAuth credentials/setup
  • Users management: create/edit/activate/deactivate/reset + approve/reject registration requests

Dashboard & Requests

  • Dashboard summaries/KPIs; Requests list/form/detail with scopes (ALL / My Tasks / My Requests)
  • Status workflow & audited transitions (PENDING→ASSIGNED→IN_PROGRESS→COMPLETED→CLOSED, etc.) with role/remarks rules

Completed Modules (2/2)

Assets & Operations

  • Facilities and Equipment: search/filter, add/edit, archive/restore, condition/status tracking
  • Schedules: maintenance scheduling and mark-done (advances next due date)

Monitoring & Reporting

  • Audit Log: read-only activity trail
  • Reports: date-range summaries, breakdowns, repair cost/downtime insights, CSV & PDF export

UI/Branding

  • Green & Gold theme, sidebar + top bar layout; updated login branding (DEIHS logo/text, centered layout)

Testing & Safety Status (as of Nov 16, 2026)

Build & Smoke Checks

  • Maven package/tests: PASS (mvn -B test / package -DskipTests). No automated unit test suite yet (src/test empty).
  • Backend smoke test (temp DB, seeded schema): PASS — logins for all roles, core DAO/service queries, reports, dashboards, auth failure handling, registration pending flow.
  • UI smoke test (FXML load, offscreen): PASS — Login, Shell, Dashboard, Requests/Form/Detail, Facilities, Equipment, Users, Schedules, Reports, Audit Log load without runtime errors.

Safety Measures in Place

  • Passwords hashed (BCrypt/jBCrypt); role-based access checks in services/UI; parameterized DB access; audit logging of key actions.
  • Config-driven DB/OAuth (no hardcoded secrets); Google sign-in hidden when not configured.

Known Limits & Risks (be transparent)

  • Google OAuth not end-to-end verified until real Client ID/Secret, redirect URI, and internet/browser access are configured and tested.
  • Photo attachments stored as local paths — not accessible across LAN PCs without a shared/network folder strategy.
  • No automated test suite yet; runtime behavior on real XAMPP/LAN and multiple client PCs still needs full validation.
  • Minor gaps to polish: e.g. Users edit does not prefill email/phone; report/export edge cases under real data volumes.
  • Security hardening advisable for real use (strong DB credentials, backups, least-privilege DB user, input/permission review).
  • Stability depends on correct DB configuration and network connectivity to the shared MySQL host.

Task Plan — Part 1: Environment & Deployment

Owner suggestion: Deployment/Infra lead

Tasks

  • Set up shared MySQL/MariaDB host (XAMPP/server) on LAN; import database/deihs_mms.sql and verify schema/data.
  • Create/secure DB user & password (avoid blank root); configure db.properties or -Ddb.* for all client PCs.
  • Prepare client run setup (Java 21, Maven or packaged JAR); document LAN IP/port and connection steps.
  • Test multi-PC connectivity (2–3 clients simultaneously) and fix connection/config issues.

Deliverable
