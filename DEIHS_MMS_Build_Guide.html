Part 0: Overview — What We Are Building and How It Fits Together

Goal of this guide: explain, step by step and in beginner-friendly terms, how to build the entire DEIHS Maintenance Management System from the beginning to the end. This is not just a list of finished features — it is a build skeleton: what each part does, why we do it that way, the important code, and how files connect.

How to use this: Read parts in order (1 → 13). Each part tells you (1) what you are building, (2) the logic/reasoning, (3) the key files and code, and (4) how it flows into the next part. Use the progress presentation for status; use this guide to learn, rebuild, and explain the system to your group.

Big picture (how the whole system works)

  • UI JavaFX screens are defined in FXML and styled with CSS. Controllers handle button clicks and fill tables/forms.
  • Logic Services enforce rules: permissions, validation, status workflow, and auditing.
  • Data DAOs run SQL (JDBC) against MySQL/MariaDB through a shared HikariCP pool. Models hold data (User, Facility, Request...).
  • Flow User action → Controller → Service (check/validate) → DAO (SQL) → Database → back to Controller → UI updates.
deihs-mms/ ├─ pom.xml (Maven build & dependencies) ├─ database/ │ └─ deihs_mms.sql (create tables + seed data) └─ src/main/ ├─ java/com/deihs/mms/ │ ├─ Launcher.java, Main.java (app start) │ ├─ config/AppConfig.java (reads db.properties / -D overrides) │ ├─ db/Database.java (HikariCP pool & connections) │ ├─ model/ (User, Role, Facility, Request, ...) │ ├─ dao/ (SQL queries per table/feature) │ ├─ service/ (rules, permissions, session, auth) │ ├─ controller/ (screen logic, wired to FXML) │ └─ util/ (ViewLoader, alerts, format, icons...) └─ resources/com/deihs/mms/ ├─ view/ (FXML screens) ├─ css/styles.css (theme/colors/layout) ├─ img/ (logo/images) └─ db.properties (DB host/port/name/user/pass + Google)

LAN setup: one PC runs MySQL (XAMPP) and all PCs run this JavaFX app pointed at that host IP.

Part 1: Prerequisites & Project Setup (Maven, Folders, pom.xml)

1.1 What you need (tools)

  • JDK 21 — compile and run Java.
  • Maven — downloads libraries and builds the project.
  • MySQL/MariaDB (XAMPP) — database server.
  • IDE (IntelliJ / VS Code + Java / NetBeans).
Why Maven? Instead of manually downloading JavaFX, MySQL driver, BCrypt, etc., Maven reads pom.xml and fetches exact versions for everyone — consistent for the whole team.

1.2 Standard project structure

deihs-mms/ ├─ pom.xml ├─ database/deihs_mms.sql └─ src/ └─ main/ ├─ java/ (all .java source, in packages com.deihs.mms.*) └─ resources/ (FXML, CSS, images, db.properties in same package paths)
Important: FXML/CSS/images go under src/main/resources so getResource(...) can find them at runtime.

1.4 Why these dependencies?

  • javafx-controls/fxml: UI toolkit and XML screen layouts.
  • mysql-connector-j: JDBC driver to talk to MySQL.
  • HikariCP: connection pool (reuses DB connections — fast/safe).
  • jBCrypt: password hashing (never store plain passwords).
  • PDFBox/Gson: PDF export and JSON (e.g. OAuth responses).
  • Launcher: required indirection so a fat JAR can start JavaFX.

Part 2: Database Design & SQL (schema, relationships, import)

2.1 Build the data layer first

Tables store users/roles, facilities, equipment, maintenance requests (and comments/history/attachments), schedules, records, audit logs, and pending account requests.

Why DB first? The UI and code follow the data. Clear tables, foreign keys, and statuses prevent confusion (permissions, workflow states, relationships).

2.2 Core tables (simplified)

TablePurpose
rolesFixed roles (ADMIN, MAINT_HEAD, PERSONNEL, STAFF) — codes used in Java.
usersAccounts: username, password_hash, role FK, active flag, profile.
account_requestsPending self-registration/Google sign-up requests.
facilities, equipmentAssets to monitor and link to requests.
maintenance_requestsMain workflow item (status, priority, requester, assignee, asset links).
request_comments/history/attachmentsDiscussion, status change trail, photo/file paths.
maintenance_schedules, maintenance_recordsPlanned work and completed work/costs.
audit_logsWho did what, when.

Part 3: Configuration & Database Connection (db.properties, AppConfig, HikariCP)

3.1 Configuration: db.properties

Holds connection info (and Google settings) so we don't hardcode values. For LAN, set db.host to the server PC's IP.

db.host=127.0.0.1
db.port=3306
db.name=deihs_mms
db.user=root
db.password=
db.pool.size=10

# Google OAuth (desktop loopback). Set these to enable "Continue with Google".
# Obtain from Google Cloud Console (OAuth 2.0 Client ID). Leave blank to disable.
google.clientId=
google.clientSecret=

            }
        }
    }

/**
 * Authentication is the only place a password is ever compared. The role is
 * read from the database — never chosen by the user at login.
 */
public class AuthService {

    private final UserDao userDao = new UserDao();
    private final AuditDao auditDao = new AuditDao();

    public User login(String username, String password) throws AuthException, SQLException {
        String name = username == null ? "" : username.trim();
        if (name.isEmpty() || password == null || password.isEmpty()) {
            throw new AuthException("Enter your username and password.");
        }

        Optional<UserCredentials> found = userDao.findByUsername(name);
        if (found.isEmpty()) {
            // Same message for unknown user and wrong password: do not leak which accounts exist.
            throw new AuthException("Invalid username or password.");
        }

        UserCredentials creds = found.get();
        if (!creds.user().active()) {
            throw new AuthException("This account has been deactivated. Contact the administrator.");
        }

        if (!BCrypt.checkpw(password, creds.passwordHash())) {
            auditDao.log(creds.user().id(), "LOGIN_FAILED", "USER",
                    String.valueOf(creds.user().id()), "Incorrect password");
            throw new AuthException("Invalid username or password.");
        }

        userDao.touchLastLogin(creds.user().id());
        auditDao.log(creds.user().id(), "LOGIN", "USER",
                String.valueOf(creds.user().id()), "Signed in");

        return creds.user();
    }

    public static String hashPassword(String plain) {
        return BCrypt.hashpw(plain, BCrypt.gensalt(10));
    }

7.1 DAO pattern (Data Access Object)

A DAO contains only database code (SQL). It maps ResultSet rows to models. Use parameterized queries (?) to prevent SQL injection.

import java.sql.Connection;

import java.sql.ResultSet;
import java.sql.SQLException;
import java.sql.Timestamp;
import java.time.LocalDateTime;
import java.util.ArrayList;
import java.util.List;

public class UserDao {

    private static final String BASE_SELECT = """
            SELECT u.user_id, u.employee_no, u.username, u.password_hash,
                   u.first_name, u.last_name, u.department, u.is_active, u.last_login,
                   r.role_code
            FROM users u
            JOIN roles r ON r.role_id = u.role_id
            """;

    public Optional<UserCredentials> findByUsername(String username) throws SQLException {
        String sql = BASE_SELECT + " WHERE u.username = ?";
        try (Connection c = Database.getConnection();
             PreparedStatement ps = c.prepareStatement(sql)) {
            ps.setString(1, username);
            try (ResultSet rs = ps.executeQuery()) {
                if (rs.next()) {
                    return Optional.of(new UserCredentials(mapUser(rs), rs.getString("password_hash")));
                }
            }
        }
        return Optional.empty();
    }

    public Optional<User> findById(int id) throws SQLException {
        String sql = BASE_SELECT + " WHERE u.user_id = ?";
        try (Connection c = Database.getConnection();
             PreparedStatement ps = c.prepareStatement(sql)) {
            ps.setInt(1, id);
            try (ResultSet rs = ps.executeQuery()) {
                if (rs.next()) {
                    return Optional.of(mapUser(rs));
                }
            }
        }
        return Optional.empty();
    }

    /** Find active user by email (case-insensitive). */
    public Optional<User> findActiveByEmail(String email) throws SQLException {
        if (email == null || email.isBlank()) return Optional.empty();

        try (Connection c = Database.getConnection();
             PreparedStatement ps = c.prepareStatement(sql)) {
            ps.setString(1, email.trim());
            try (ResultSet rs = ps.executeQuery()) {
                if (rs.next()) {
                    return Optional.of(mapUser(rs));
                }
            }
        }
        return Optional.empty();

                       OR f.facility_type LIKE ?)

    public int create(FacilityDraft draft, User user)
            throws ValidationException, SQLException {
        requireManage(user);
        FacilityDraft clean = clean(draft);
        validate(clean);

        if (facilityDao.existsCode(clean.code(), 0)) {
            throw new ValidationException(
                    "Facility code " + clean.code() + " is already in use. Choose another.");
        }

        int id = facilityDao.create(clean);
        auditDao.log(user.id(), "CREATE_FACILITY", "facilities", clean.code(),
                clean.name());
        return id;
    }

    public void update(int id, FacilityDraft draft, User user)
            throws ValidationException, SQLException {
        requireManage(user);
        FacilityDraft clean = clean(draft);
        validate(clean);

        if (facilityDao.existsCode(clean.code(), id)) {
            throw new ValidationException(
                    "Facility code " + clean.code() + " is already in use. Choose another.");
        }

        facilityDao.update(id, clean);
        auditDao.log(user.id(), "UPDATE_FACILITY", "facilities", clean.code(),
                clean.name());
    }

            throws ValidationException, SQLException {
        requireManage(user);
        facilityDao.setActive(id, active);
        auditDao.log(user.id(), active ? "RESTORE_FACILITY" : "ARCHIVE_FACILITY",

Part 10: Accounts: Registration, User Management & Google Sign-in (Option A)

10.1 Self-registration (pending approval)

  • User submits form → RegistrationService validates and inserts into account_requests (hashed password, requested role, PENDING).
  • Admin approves (creates/activates user with chosen role) or rejects.
Why pending approval? Admin controls who gets access and which role — prevents unauthorized privileged accounts.

10.2 Users management

Admin: create/edit, activate/deactivate, reset passwords, approve/reject requests. Pattern: Controller → UserService/RegistrationService → UserDao/AccountRequestDao (+ audit).

10.3 Google sign-in (Option A, config-gated)

  • Shown only if google.clientId configured (GoogleOAuthService.isConfigured()).
  • Desktop loopback+browser OAuth (PKCE) → verified email/profile.
  • Match active user by email → sign in. Inactive → blocked message. No match → collect required fields/requested role and submit pending request.
Pending in dev: needs real Client ID/Secret, redirect URI, internet/browser, and matching emails. Keep secrets in config/-D, never hardcoded.

12.3 LAN deployment checklist

  1. Server PC: run MySQL/XAMPP, import database/deihs_mms.sql, create secured DB user, note LAN IP.
  2. Client PCs: install Java 21, copy app, set db.host=<server-ip> (port/user/pass) via properties or -D.
  3. Verify: login from multiple PCs, perform CRUD, confirm shared data updates.

12.4 Testing approach

  • Build/tests pass: mvn -B test, package.
  • Smoke per role (ADMIN, MAINT_HEAD, PERSONNEL, STAFF): menus and allowed actions.
  • Workflow: create → assign → progress → complete → close request; check history/audit.
  • Failures: wrong password, DB unreachable, invalid input → friendly errors, no crash.
Notes: dev db.properties may point to a dev port (e.g. 3307) — set to XAMPP/LAN for deployment. Photo attachments are local paths (shared folder needed across PCs). No automated unit tests yet.
